Demo 11 · The mechanisms

Ask For The Error, Not The Wrong Answer

Ask a generator for "three plausible wrong answers" and you get options that are mathematically valid and pedagogically empty. Invert the request — name the misconception, apply it deterministically, derive the option — and the same item starts telling you what the learner actually did.

Computed live Both generators run in the page
What this is

Two multiple-choice generators on the same stem, side by side. One asks for plausible wrong answers. The other models a named misconception first and derives the option from it.

Why it matters

LLMs produce distractors that are mathematically valid and pedagogically empty. They are “less adept at anticipating common errors among real students”, and that survived fine-tuning. Modelling the error as a first-class object lets a 7B model beat GPT-4o.

How to use it

Generate from both and compare. Generator A's options are a function of the key, so a student choosing one tells you nothing. Generator B's map to specific errors, which makes a wrong answer diagnostic. Watch the collision counter reject options that two misconceptions would both produce.

Computed means: both generators below really execute on the parameters you set. The collision checks, the plausibility filter, the diagnosticity accounting and the parameter sweep at the bottom are all real computation on real output, performed when you move a slider.

One honesty note before you start. Generator A is not an LLM and this page does not claim to measure one. It is a deterministic stand-in: a generator that is conditioned on the answer and nothing else. The reason that stand-in is fair is structural rather than empirical, and it is stated precisely in §3. Any option set that is a function of the key alone cannot carry information about which error was made. The empirical claim that real LLMs behave this way rests on the citations in §5. This page measures nothing about any model.

3 · Why the comparison is structural

The one-line argument

Let K be the key, E the error the learner actually made, and O the option they selected.

Generator A: options = f(K) ⇒ O ⫫ E given K ⇒ P(E | O, K) = P(E | K) ⇒ the response carries ZERO information about the error. Generator B: options = g(E_i, stem-parameters), one per named error ⇒ O identifies E_i, PROVIDED g is injective over the error set ⇒ the injectivity check is the whole engineering problem, and it is the collision filter in §2.

This is why "make the distractors more plausible" is not a fix and never was. Plausibility is a property of the option's surface. Diagnosticity is a property of the map from errors to options, and you cannot get it by improving a generator that never had an error variable in it. That is the whole content of the DiVERT result: it makes the error an explicit latent object, represented as text, rather than hoping it falls out of a fluent generator.

Why the error distribution is not recoverable from a corpus. An LLM's prior over "wrong answer" is a prior over plausible text, learned from a corpus in which correct answers dominate and student errors are rare and unlabelled. The empirical distribution of student errors is a different distribution entirely, and it is not recoverable from text describing the domain. It is recoverable only from response data — which is exactly what the error bank in this demo is a hand-built stand-in for, and exactly what a real system would have to mine.

What this proves / what it does not

What this page proves
  • That error-first generation is fully mechanical. Given a named misconception and a deterministic transformation, the option falls out; change the stem's numbers and the option follows the error rather than the answer. You can watch that happen on a slider.
  • That the hard part is collision, not creativity. The sweep shows a real, non-trivial fraction of parameter settings where two distinct misconceptions land on the same value, or where a misconception lands on the key. Those items look fine and cannot discriminate. A generator without this check ships them silently.
  • That the advantage is structural. An option set that is a function of the key alone is provably uninformative about the error. No amount of plausibility tuning changes that, because plausibility and diagnosticity are different properties.
What this page does not prove
  • Nothing about LLMs. No model runs here. Generator A is a stand-in chosen to have one property — conditioning on the answer only — and the claim that real LLM distractor generation shares that property is Feng et al.'s measurement, not this page's.
  • That the error bank is right. The misconceptions here are hand-authored from the well-known literature on fraction and equation errors. A real system's bank must be mined from response data and its frequencies estimated, because which errors are common is an empirical question and the whole diagnostic value depends on the answer.
  • That items built this way measure better. Diagnosticity is a property of the item's design; whether the resulting items have adequate discrimination, difficulty and dimensionality is a psychometric question that requires response data from real students. Nothing here is a substitute for field-testing.
  • That a misconception-derived distractor teaches better. It carries more diagnostic information. That is a property of the item; no learning gain was measured here.
